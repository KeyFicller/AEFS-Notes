A

速览

create_agent(model, tools, middleware=[...]) 在 ReAct 循环外面再套一层。中间件在固定位置读写 state，并拦截模型请求和工具执行。

对照本机 langchain 1.4.2 / langchain-core 1.6.4 核对。练习见 codes/langchain/10_middleware/qa.ipynb。

约定：

  • before_agent 和 after_agent 每次 invoke 各跑一次。中间三个钩子每轮模型调用都跑。
  • 一次 invoke 不等于一次模型调用。有工具往返时模型会被调多次。
  • middleware=[A, B] 里越靠前越在外层。wrap_* 是洋葱模型：A 进 → B 进 → B 出 → A 出。
  • 装饰器只能写无状态小钩子。要自己存字段就写成 AgentMiddleware 子类。
B

六个钩子

钩子 签名 时机 返回值
before_agent (state, runtime) 整个 agent 开始前，一次 state 更新 dict 或 None
before_model (state, runtime) 每次调模型之前 state 更新 dict 或 None
after_model (state, runtime) 每次调模型之后 state 更新 dict 或 None
after_agent (state, runtime) agent 结束时，一次 state 更新 dict 或 None
wrap_model_call (request, handler) 包住每次模型调用 ModelResponse
wrap_tool_call (request, handler) 包住每次工具执行 ToolMessage 或 Command

装饰器与类方法同名，作用是把函数包成单例中间件：

装饰器 类里的等价写法 要点
@before_model def before_model(...) 返回 None 表示不改 state
@after_model def after_model(...) 同理
@wrap_model_call def wrap_model_call(...) 必须自己调 handler(request)
@wrap_tool_call def wrap_tool_call(...) 不调 handler 就等于跳过工具
@dynamic_prompt def wrap_model_call(...) 按运行时上下文算 system prompt
  • 每个钩子都有异步版，加 a 前缀：abefore_model、awrap_tool_call 等。
  • @hook_config(can_jump_to=[...]) 声明允许的跳转目标，取值只有 "tools"、"model"、"end"。
  • 钩子返回 {"jump_to": "end"} 可提前结束循环。
C

类式中间件

三个类属性决定中间件怎么接入：

属性 作用
state_schema 声明扩展的 state 字段。不写也能跑，但 return {"calls": 1} 会被静默丢弃
tools 中间件自带的工具，自动并入 agent 的工具集
name 默认取类名，用于追踪

AgentState 自带三个字段：messages、jump_to、structured_response。扩展字段要给默认值或标 NotRequired，否则第一次进钩子会 KeyError。

钩子拿到的两个请求对象：

对象 字段 出现在
ModelRequest model、messages、system_message、tool_choice、tools、response_format、state、runtime、model_settings wrap_model_call
ToolCallRequest tool_call、tool、state、runtime wrap_tool_call

request.override(...) 返回改过的副本。system_message 默认是 None，只有设了 system_prompt 才有值；messages 是这次要发的完整历史。

官方中间件一览

按用途分组。「钩子」一列是它实际覆写的位置。

上下文管理

类 关键参数 钩子 做什么
SummarizationMiddleware model、trigger=("messages", 20)、keep=("messages", 20)、token_counter before_model 历史超阈值时压成摘要，只留最近几条
ContextEditingMiddleware edits=[ClearToolUsesEdit()]、token_count_method wrap_model_call 按规则裁剪旧的工具结果，默认触发线 10 万 token

可靠性

类 关键参数 钩子 做什么
ToolRetryMiddleware max_retries=2、tools、retry_on、on_failure='continue'、initial_delay=1.0、backoff_factor=2.0、jitter=True wrap_tool_call 工具失败自动重试，指数退避
ModelRetryMiddleware 同上 wrap_model_call 模型调用失败自动重试
ModelFallbackMiddleware first_model, *additional_models wrap_model_call 主模型报错时换备用模型
ToolErrorMiddleware on_error、tools wrap_tool_call 把指定工具的异常转成给模型看的 ToolMessage

限流

类 关键参数 钩子 做什么
ModelCallLimitMiddleware run_limit、thread_limit、exit_behavior='end' before_model、after_model 卡模型调用次数，按单次 run 或整个 thread 计
ToolCallLimitMiddleware tool_name、run_limit、thread_limit、exit_behavior='continue' after_model 卡工具调用次数，可只针对某个工具

两个限流的 exit_behavior 决定超限后的走向。模型限流取 'end' / 'error'；工具限流取 'continue' / 'end' / 'error'。

使用用例

1. 装饰器写两个观察钩子

from langchain.agents import create_agent
from langchain.agents.middleware import after_model, before_model


@before_model
def spy_before(state, runtime):
    print("[before_model]", len(state["messages"]))
    return None


@after_model
def spy_after(state, runtime):
    print("[after_model]", len(state["messages"]))
    return None


agent = create_agent("deepseek:deepseek-chat", tools=[add], middleware=[spy_before, spy_after])
agent.invoke({"messages": [HumanMessage("用工具算 2+3")]})
# 两个钩子各打两行：模型被调两次，而 invoke 只有一次

2. 类式中间件加自己的 state 字段

from typing import NotRequired

from langchain.agents.middleware import AgentMiddleware, AgentState


class MyState(AgentState):
    calls: NotRequired[int] = 0


class CountCalls(AgentMiddleware):
    state_schema = MyState

    def before_model(self, state, runtime):
        return {"calls": state.get("calls", 0) + 1}


agent = create_agent("deepseek:deepseek-chat", tools=[add], middleware=[CountCalls()])
print(agent.invoke({"messages": [HumanMessage("用工具算 2+3")]})["calls"])  # 2

3. 改这次要发的系统提示

from langchain.agents.middleware import wrap_model_call


@wrap_model_call
def inject(request, handler):
    print("字段:", list(request.__dataclass_fields__))
    print("system_message:", request.system_message)
    return handler(request.override(system_prompt="回答结尾补一句「已核对」"))

4. 工具失败时兜底

from langchain.agents.middleware import ToolRetryMiddleware, wrap_tool_call
from langchain_core.messages import ToolMessage


@wrap_tool_call
def catch(request, handler):
    try:
        return handler(request)
    except Exception as exc:
        return ToolMessage(content=f"工具执行失败：{exc}", tool_call_id=request.tool_call["id"])

ToolRetryMiddleware(max_retries=2, initial_delay=0.1) 做的是另一件事：固定重试，最终还是把异常抛到上层。

5. 给 agent 装上限

from langchain.agents.middleware import ModelCallLimitMiddleware, ToolCallLimitMiddleware

ModelCallLimitMiddleware(run_limit=1, exit_behavior="end")
ToolCallLimitMiddleware(tool_name="add", run_limit=0, exit_behavior="continue")

6. 历史太长自动摘要

from langchain.agents.middleware import SummarizationMiddleware

SummarizationMiddleware(
    model="deepseek:deepseek-chat",
    trigger=("messages", 4),
    keep=("messages", 2),
)

7. 工具审批要配 checkpointer

from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import Command

agent = create_agent(
    "deepseek:deepseek-chat",
    tools=[add],
    middleware=[HumanInTheLoopMiddleware(interrupt_on={"add": True})],
    checkpointer=MemorySaver(),
)
cfg = {"configurable": {"thread_id": "t1"}}
first = agent.invoke({"messages": [HumanMessage("用工具算 2+3")]}, config=cfg)
print(first["__interrupt__"][0].value)  # action_requests + review_configs
agent.invoke(Command(resume={"decisions": [{"type": "approve"}]}), config=cfg)
F

常见坑

  • 忘了 state_schema：return {"calls": 1} 不报错，但键直接消失。这是最难查的一类坑。
  • 扩展字段要标 NotRequired 或给默认值，否则第一次进钩子读不到就 KeyError。
  • state 字段活在 state 里，不在中间件实例上。结果读 response["calls"]，不是 middleware.calls。
  • wrap_model_call 忘了 return handler(request)，模型就不会被调用。
  • wrap_tool_call 的 except 里要自己造 ToolMessage，tool_call_id 取 request.tool_call["id"]。
  • ToolRetryMiddleware 重试完仍会抛异常。想彻底兜住就用 wrap_tool_call 自己接。
  • 限流的 exit_behavior：'continue' 把限制做成正常消息让流程走下去，'error' 直接抛 ModelCallLimitExceededError 或 ToolCallLimitExceededError。
  • HumanInTheLoopMiddleware 的 decisions 长度必须等于挂起的工具调用数。给多给少都会 ValueError。
  • SummarizationMiddleware 的摘要在每次调模型前重算，不写回 state。最终 state 的条数和进模型的条数对不上。
