A

速览

按主题分组的常用 API。签名与默认值对照本机 langgraph 1.2.12 / langgraph-checkpoint 4.2.0 / langgraph-prebuilt 1.1.0（配套 langchain 1.4.2 / langchain-core 1.6.4）核对，= 后面是默认值，没写默认值的表示必填。阶段练习见 index.md。

约定：

  • 「编译后的图」= StateGraph(...).compile() 的返回值。StateGraph 本身只是画布，没有 invoke。
  • 节点是普通函数：入参是整份 state，返回部分 state（{"字段": 新值}）；返回 None 表示这一步不改任何字段。
  • config 就是 RunnableConfig：{"configurable": {"thread_id": ...}, "recursion_limit": ...}。thread_id 住在 configurable 里，recursion_limit 在顶层。
  • 同名的 a 前缀（ainvoke / astream / aget_state）都是异步版，签名与同步版一致。
  • 本模块模型统一 init_chat_model("deepseek:deepseek-v4-flash")，密钥读 DEEPSEEK_API_KEY（放 codes/langgraph/local.env）。
B

API 速查

子模块一览

子模块 里面有什么
graph StateGraph、START / END、MessagesState、add_messages
graph.message add_messages、MessagesState
types Command、interrupt、Send、RetryPolicy、CachePolicy、StateSnapshot、StreamMode、Durability
checkpoint.memory MemorySaver（= InMemorySaver，同一物）
prebuilt ToolNode、tools_condition、create_react_agent（已弃用，改用下面的 create_agent）
config get_config、get_store、get_stream_writer
errors GraphRecursionError、GraphInterrupt、InvalidUpdateError、EmptyInputError
langchain.agents create_agent（预置 ReAct 图，在 langchain 包里，不在 langgraph）

简写对照：graph = langgraph.graph，graph.message = langgraph.graph.message，types = langgraph.types，checkpoint.memory = langgraph.checkpoint.memory，prebuilt = langgraph.prebuilt，config = langgraph.config，errors = langgraph.errors。

图骨架：State / 节点 / 边

名称 子模块 常用关键字参数 说明
StateGraph graph state_schema、context_schema=None、input_schema=None、output_schema=None 建画布。state_schema 常用 TypedDict；input_schema / output_schema 想收窄入口 / 出口时才给
START / END graph — 两个哨兵常量，实际值就是字符串 '__start__' / '__end__'，所以能直接当 path_map 的键
add_node graph node、action=None、defer=False、input_schema=None、retry_policy=None、cache_policy=None、destinations=None 注册节点；add_node("agent", fn)，或 add_node(fn) 直接拿函数名当节点名
add_edge graph start_key、end_key 静态边，写死去向；start_key 可以传 list 做 fan-in
add_conditional_edges graph source、path、path_map=None path 是 router 函数，读 state 返回节点名或 END；path_map 可给 dict 或 list，不给时要求 router 的返回值本身就是节点名
set_entry_point / set_finish_point graph key 就是 add_edge(START, key) / add_edge(key, END) 的简写
compile graph checkpointer=None、cache=None、store=None、interrupt_before=None、interrupt_after=None、debug=False、name=None 出可跑的图。interrupt_before/after 收节点名列表，也可以直接给 "*"
get_graph 编译后的图 config=None、xray=False 拿结构；app.get_graph().nodes.keys() 看节点名，draw_mermaid() 出文本（draw_mermaid_png() 要联网）

router 不是节点：只 add_conditional_edges(..., router, ...)，别 add_node("router", router)。

State 与 reducer

名称 子模块 常用关键字参数 说明
TypedDict typing — 声明 state 字段；class S(TypedDict): text: str
Annotated typing type、reducer 给字段挂 reducer：items: Annotated[list, add_messages]
add_messages graph.message left=None、right=None 官方的消息 reducer：追加；同 id 的消息是替换而不是新增；RemoveMessage(id=...) 可删，但 id 必须已存在
MessagesState graph — 预置 state，只有一个 messages 字段且已配好 add_messages，等价于 Annotated[list[AnyMessage], add_messages]

字段不写 reducer 默认是覆盖：新值直接换掉旧值。所以「历史累加」一定要 Annotated[..., add_messages] 或直接用 MessagesState。

运行

名称 子模块 常用关键字参数 说明
invoke 编译后的图 input、config=None、context=None、stream_mode='values'、output_keys=None、interrupt_before=None、interrupt_after=None、durability=None 跑到底，返回最终 state（dict）。断点续跑时 input 传 None
stream 编译后的图 input、config=None、stream_mode=None、output_keys=None、subgraphs=False、debug=None、durability=None 返回迭代器，每推进一步 yield 一块
astream 编译后的图 同 stream 异步迭代器，配 async for；节点是同步 def 也能流，LangGraph 会丢进线程跑
GraphRecursionError errors — 步数超 recursion_limit 抛它（RecursionError 的子类），被中断的重放相关的是 GraphInterrupt

stream_mode 取值（StreamMode）：'values'（全量 state）、'updates'（只含刚写回的部分，key 是节点名）、'messages'（逐 token，(AIMessageChunk, metadata)，metadata["langgraph_node"] 是出处）、'custom'（配 get_stream_writer() 自己吐）、'checkpoints'、'tasks'、'debug'。

stream_mode 传列表时同时吐多种，每块变成 (mode, data) 元组；单模式时直接是 data。

durability（'sync' / 'async' / 'exit'）控制 checkpoint 落盘时机，默认随 checkpointer 走。

持久化与线程

名称 子模块 常用关键字参数 说明
MemorySaver checkpoint.memory — 内存 checkpointer，compile(checkpointer=...) 装上；等于 InMemorySaver，进程退出即失
config — {"configurable": {"thread_id": ...}} 线程 id 决定 state 分桶；换一个 thread_id 就是另一个互不可见的会话
get_state 编译后的图 config、subgraphs=False 取当前快照，返回 StateSnapshot
get_state_history 编译后的图 config、filter=None、before=None、limit=None 从新到旧产快照的迭代器，list(...) 后再数
update_state 编译后的图 config、values、as_node=None、task_id=None 把 values 当成 as_node 的输出合并进 state；只改 state，不推进图，要接着跑还得 invoke(None, config)。返回带 checkpoint_id 的新 config

StateSnapshot 常用属性：values（完整 state）、next（下一步要执行的节点元组，跑完是 ()）、config（带 thread_id / checkpoint_id）、metadata、created_at、parent_config、tasks、interrupts。

next == ('agent',) 表示停在该节点即将执行的位置，是后面做中断 / 时光倒流的锚点。

人机协同（HITL）

名称 子模块 常用关键字参数 说明
interrupt_before / interrupt_after compile ["writer"] 或 "*" 静态断点，钉在节点边界。after 上一个 与 before 下一个 是同一位置；钉在最后一个节点之后的收尾断点，next 退化成 ()
get_state(config).next 编译后的图 — 静态断点停在哪儿只能从这儿看：返回结果里没有 __interrupt__，keys 就是 ['messages']
invoke(None, config) 编译后的图 — 从静态断点续跑
interrupt types value、response_schema=None 在节点内部暂停，value 是给人看的 payload；续跑时这个调用直接返回人的答复
Command types graph=None、update=None、resume=None、goto=() Command(resume=人的答复) 续跑动态中断；也可用 update / goto 改状态或跳转
__interrupt__ — — 触发动态中断那次 invoke 的返回里多出的键，取 result["__interrupt__"][0].value 就是 payload

静态和动态的分界：静态断点看 next，动态 interrupt() 看 __interrupt__。

预置零件

名称 子模块 常用关键字参数 说明
ToolNode prebuilt tools、name='tools'、handle_tool_errors=_default_handle_tool_errors、messages_key='messages'、wrap_tool_call=None 现成节点：读最后一条 AIMessage 的 tool_calls，逐个执行并包成 ToolMessage 写回。取代手写 run_tools
tools_condition prebuilt state、messages_key='messages' 官方版 should_continue：有 tool_calls 返回 'tools'，否则返回 '__end__'。可以不传 path_map
create_agent langchain.agents model、tools=None、system_prompt=None、middleware=()、response_format=None、state_schema=None、checkpointer=None、store=None、interrupt_before=None、interrupt_after=None、debug=False、name=None、cache=None 一行建好整张 agent ↔ tools 图，返回已编译的图，照样能 stream / 接 checkpointer / 下断点
create_react_agent prebuilt 旧签名（prompt= 而非 system_prompt=） 已弃用，会提示改用 langchain.agents.create_agent

节点名对比（interrupt_before / as_node 都按节点名匹配，写错会静默失效）：

节点名
预置 create_agent(model, tools) __start__ / model / tools / __end__
手写 agent + ToolNode + tools_condition __start__ / agent / tools / __end__

差异只在模型节点叫 model 还是 agent。建完图先 sorted(app.get_graph().nodes.keys()) 看一眼是好习惯。

ToolNode 的默认容错范围比多数人以为的小：默认的 _default_handle_tool_errors 只把 ToolInvocationError（工具名 / 参数不合规这类「真正调用工具之前」的失败）转成 ToolMessage；工具函数体自己抛的 ValueError 之类会原样重抛把图炸掉。要兜住就显式 ToolNode(tools, handle_tool_errors=True)。

重试与缓存

名称 子模块 常用关键字参数 说明
RetryPolicy types initial_interval=0.5、backoff_factor=2.0、max_interval=128.0、max_attempts=3、jitter=True、retry_on=<default_retry_on> 挂给 add_node(..., retry_policy=...)；默认只重试连接类错误和 5xx
CachePolicy types key_func=<default_cache_key>、ttl=None 节点级缓存，配 compile(cache=...) 用
Send types node、arg、timeout=None map-reduce fanout 的载体，本模块暂未练

步数限制与错误

名称 子模块 说明
recursion_limit config 顶层键 执行步数的硬上限，不是「最多几轮对话」。本机默认 10007，可用环境变量 LANGGRAPH_DEFAULT_RECURSION_LIMIT 改
GraphRecursionError errors 步数超上限时抛（RecursionError 子类），消息里带 Recursion limit of N reached
GraphInterrupt / InvalidUpdateError / EmptyInputError errors 中断 / 更新非法 / 空输入

正常图也要给 recursion_limit 留余量，设小了会直接 GraphRecursionError，不是图写错了。

常见坑

  • 字段名三处必须逐字一致：State 定义、节点返回的键、invoke 传入的键。对不上时 LangGraph 不报错，只静默丢掉更新——轻则 None，重则整份 state 为空。
  • 节点必须返回部分 state（dict），不是整份；返回 {"messages": [msg]} 而不是 {"messages": msg}，多套一层列表是把 list 塞进了消息列表里。
  • 默认 reducer 是覆盖，不是追加。要在 MessagesState 之外自己收消息，必须 Annotated[list, add_messages]。
  • tool_calls 每一项是 {"name", "args", "id", "type"} 的 dict，取值用中括号：call["name"] / call["args"] / call["id"]；执行工具用 tools_by_name[call["name"]].invoke(call["args"])，StructuredTool 不能直接当函数调，*call.args 也会把字典键当位置参数展开。
  • 回填工具结果用 ToolMessage(content=str(result), tool_call_id=call["id"])——tool_call_id 必填且要和发起的 id 对上；ToolMessage 没有 args / observation 字段，结果放 content。
  • router 是路由函数不是节点，别 add_node；循环（条件边指回自己）必须留出口，有分支就 return END 才停得下来。返回 END 和返回字符串 "__end__" 等价。
  • recursion_limit 是执行步数上限，正常图也要留余量；设小了会 GraphRecursionError，不是图写错了。
  • 静态断点（interrupt_before / interrupt_after）的返回里没有 __interrupt__，停在哪儿看 get_state(config).next；只有动态 interrupt() 才给 __interrupt__。
  • Command(resume=...) 会让被中断的节点从头再跑一遍（只是这次 interrupt() 直接返回你给的值），所以 interrupt() 之前的代码必须幂等——写文件、发请求这类副作用要自己兜。
  • update_state 只写 state，不推进图；next 不变说明它没往前走，还得 invoke(None, config) 才继续。
  • config 要写成 {"configurable": {"thread_id": ...}}。写成扁平的 {"thread_id": ...} 时 invoke 能跑（ensure_config 会把顶层不认识的键悄悄塞进 configurable），但 get_state 直接读 config["configurable"]，会 KeyError: 'configurable'。别依赖这个隐式转换。
  • 没有 checkpointer 时每次 invoke 都是全新的 state，第二轮只看到新消息、答不出上一轮的事；MemorySaver 只在内存里，进程退出就没了——落盘（SqliteSaver / Postgres）是第 7 阶段的内容，本机没装 langgraph-checkpoint-sqlite / langgraph-checkpoint-postgres。
  • messages 流里混着大量 content == "" 的空块（工具调用 / 用量信息），拼接时跳过即可；两个节点都会吐 token，想只截「说给人看」的那段得按 metadata["langgraph_node"] 挑。
  • 笔记本里直接顶层 await / async for——ipykernel 已经在跑事件循环，再调 asyncio.run(main()) 会报 RuntimeError: asyncio.run() cannot be called from a running event loop；.py 脚本里才需要 async def main() + asyncio.run(main())。
  • 节点里用 model 还是 bound = model.bind_tools(tools) 差别很大：用没绑工具的 model，模型永远不会返回 tool_calls，条件边第一次就走向 END，循环一步都不进。
