A

速览

镜像是一份只读模板。容器是镜像跑起来后多出来的一层可写层。卷把宿主机的目录挂进容器，数据就不跟着容器消失。

三条边界：

  • 环境进镜像。Python、CUDA、依赖版本都写进 Dockerfile。
  • 数据进卷。模型权重、数据集、向量库的落盘目录都挂出来。
  • 一次运行进容器。容器随 --rm 消失，镜像和卷都不受影响。

练习见 codes/docker/qa.ipynb，练习环境在 codes/docker/app/。

B

Dockerfile 指令

指令 作用 AI 场景里的写法
FROM 选底座 nvidia/cuda:12.4.1-runtime-ubuntu22.04
WORKDIR 设工作目录，后续指令都在这里 WORKDIR /app
COPY 从构建上下文拷文件 先 COPY requirements.txt .，后 COPY . .
RUN 构建时执行，结果落成一层 RUN pip install --no-cache-dir -r requirements.txt
ENV 设环境变量 ENV PYTHONUNBUFFERED=1
EXPOSE 声明端口，仅作文档 EXPOSE 8888
CMD 容器启动的默认命令 CMD ["python", "main.py"]
ENTRYPOINT 固定入口，CMD 变成默认参数 服务类镜像常用

RUN 每写一条就多一层。能合并的用 && 合并，装完删掉 apt 缓存。

C

层缓存：顺序决定重不重装

好的顺序                          坏的顺序
COPY requirements.txt .          COPY . .
RUN pip install -r ...           RUN pip install -r ...
COPY main.py .                   （改代码 → 缓存从 COPY 断掉）
  • 改 main.py 时，好的顺序只有最后一层重跑，pip install 直接 CACHED。
  • 坏的顺序里，COPY . . 一旦变化，RUN pip install 就得重跑。
  • 本机实测：重装 numpy 那一层约 26 秒。依赖一多，差距会更大。

把变化慢的放前面，变化快的放后面。这是 Dockerfile 唯一要背的规则。

D

日常命令

命令 做什么
docker build -t ai:1 . 用当前目录的 Dockerfile 建镜像
docker run --rm ai:1 跑一次，退出后删容器
docker run -it ai:1 bash 进容器交互
docker ps 看运行中的容器
docker images 看镜像和大小
docker logs -f <name> 跟日志
docker exec -it <name> bash 进一个正在跑的容器
docker cp <name>:/workspace/out.csv . 从容器拷文件出来
docker system prune -a 删没用到的镜像和缓存

docker system prune -a 会把下次要用的镜像也删掉，重跑一次构建很慢。确认清楚再用。

E

卷：模型和数据集

写法 存在哪 适合
-v $PWD:/workspace 宿主机当前目录 代码、随时要看的结果
-v ~/models:/models 宿主机家目录 14G 的权重，重建容器不重下
-v cache_data:/data Docker 命名卷 数据库、缓存，不想管路径 
docker run --rm \
  -v "$PWD:/workspace" \
  -v ~/models:/models \
  ai:1 python main.py

容器里的 /models 就是宿主机的 ~/models。删容器、重建镜像都不影响它。

命名卷的坑在 docker compose down -v：-v 连卷一起删。日常 down 只停容器，卷还在。

F

端口与 Jupyter

docker run --rm -p 8888:8888 \
  -v "$PWD:/workspace" \
  ai:1 jupyter notebook --ip=0.0.0.0 --port=8888 --no-browser --allow-root

-p 8888:8888 是 宿主机:容器。左边可以换，右边必须和容器里监听的一致。

容器里必须写 --ip=0.0.0.0。Jupyter 默认只绑 127.0.0.1，那只在容器内部可达，宿主机的端口转发进不去。

G

GPU

docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
  • Linux 先装 NVIDIA Container Toolkit，再 nvidia-ctk runtime configure。
  • macOS 的 Docker Desktop 没有 GPU 直通。--gpus 会报 no known GPU vendor found。
  • 报错发生在启动阶段，不是镜像坏了。换平台或去掉 --gpus 再跑。

底座镜像按需要选：

镜像 大小 什么时候用
nvidia/cuda:12.4.1-devel ~4 GB 要 nvcc 编译 flash-attn、bitsandbytes
nvidia/cuda:12.4.1-runtime ~1.5 GB 只跑预编译好的包
pytorch/pytorch:2.6.0-cuda12.4-cudnn9-runtime ~6 GB 省掉装 PyTorch 这一步
python:3.12-slim ~150 MB CPU 推理、工具脚本

没有 GPU 就别装 +cu124 的 torch。镜像会大出几 GB，跑起来还是 CPU。

Compose

name: docker-lab

services:
  lab:
    image: docker-lab:1
    command: ["python", "-c", "import time; time.sleep(3600)"]
    depends_on: [cache]

  cache:
    image: redis:7-alpine
    volumes:
      - cache_data:/data

volumes:
  cache_data:
命令 做什么
docker compose up -d 起全部服务
docker compose ps 看服务状态
docker compose logs -f lab 跟某个服务的日志
docker compose exec lab bash 进某个服务
docker compose down 停并删容器，保留命名卷
docker compose down -v 连命名卷一起删

同一个 compose 文件里的服务在同一个网络。lab 里直接写 cache:6379，服务名就是主机名。

换成 RAG 应用时，把 cache 换成 qdrant/qdrant 即可。连接地址还是服务名。

I

常见坑

  • COPY . . 写在 RUN pip install 前面。改一行代码，依赖全部重装。
  • --rm 不配 -v。容器里写的模型、日志、向量库，退出就没了。
  • -p 8888:8000 写成 -p 8000:8888。端口映射反了，访问不到。
  • Jupyter 忘了 --ip=0.0.0.0。容器里能开，宿主机连不上。
  • 用 down -v 清理，把命名卷里的数据一起删了。
  • 在 macOS 上试 --gpus all，把平台限制当成镜像问题。
  • docker system prune -a 删掉基础镜像，下一次构建从零开始。
