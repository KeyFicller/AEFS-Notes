A

速览

按主题分组的常用 API。签名与默认值对照本机 langchain 1.4.2 / langchain-core 1.6.4（配套 langchain-text-splitters 1.1.2、langchain-deepseek 1.1.1、langchain-huggingface 1.2.2、langchain-openai 1.6.3）核对，= 后面是默认值，没写默认值的表示必填。阶段练习见 index.md。

约定：

  • 子模块 一列用简写（见下表）。langchain 主包很薄，真正的东西大多在 langchain_core；厂商模型放在 langchain-<provider> 里。
  • Runnable 指实现了 invoke / batch / stream 的对象。表里凡是标成 Runnable 的，都通吃这三个方法，加 a 前缀（ainvoke / astream）是异步版。
  • 消息、文档这类对象的字段大多有默认值，下表只在有区别时重复。
  • 本机没装 langchain-community，文档加载器 / 第三方向量库那一节标注了「需另装」，签名未核对。

docstring 怎么进 schema

说明文字优先取 description=，没给才取函数的 docstring（__doc__ 去掉公共缩进和首尾空行）。名字同理，@tool("score") 覆盖函数名，否则用 __name__。所以 docstring 有两种读法：

写法 description 参数字段说明
默认 parse_docstring=False 整段 docstring，Args: 段原样留在里面 只来自类型注解 / Annotated，Args: 那几句白写
parse_docstring=True（只认 Google 风格） 摘要段，Args: 段被摘掉 来自 Args: 段每条，落进 args_schema

模型收到的就是这份：bind_tools 内部走 convert_to_openai_tool，function.description 和 parameters.properties.<参数>.description 直接来自上面两处。render_text_description 只是自己拼提示词用的多行文本，只有摘要和签名，要带参数说明得用 render_text_description_and_args。

Middleware（Agent 中间件）

create_agent 在模型循环外包一层钩子。一次 invoke ≠ 一次模型调用：有工具往返时，before_model / after_model / wrap_model_call 会按模型调用次数触发。全部从 langchain.agents.middleware 导入。

核心类型与钩子

名称 子模块 常用关键字参数 说明
AgentState middleware messages、jump_to、structured_response 默认 state；自定义字段要继承它再挂到 state_schema
AgentMiddleware middleware state_schema=AgentState、tools=None 类式中间件基类；重写 before_model / after_model / wrap_model_call / wrap_tool_call（及 *_agent、异步 a*）
ModelRequest middleware model、messages、system_message=None、tools、state、runtime、model_settings={} 进模型前的完整请求；messages 不含 system，system 在 system_message
ModelRequest.override middleware **overrides（如 system_prompt=...） 返回改写后的新请求，原对象不动
ModelResponse middleware result、structured_response wrap_model_call 的 handler 返回值
ToolCallRequest middleware tool_call、tool、state、runtime 工具执行前的请求；兜底时 tool_call["id"] 用来造 ToolMessage
@before_model / @after_model middleware state_schema=None、tools=None、can_jump_to=None、name=None 模型调用前 / 后；签名 (state, runtime) -> dict | None

@wrap_model_call middleware state_schema=None、tools=None、name=None (request, handler) -> ModelResponse | AIMessage；改请求后 handler(request.override(...))

自定义字段示例：class MyState(AgentState): calls: NotRequired[int]，再 class M(AgentMiddleware): state_schema = MyState，在钩子里 return {"calls": ...}。不写 state_schema 时自定义键会被静默丢弃，不报错。

HITL 最小闭环：create_agent(..., middleware=[HumanInTheLoopMiddleware(interrupt_on={"add": True})], checkpointer=MemorySaver()) → invoke(..., config={"configurable": {"thread_id": "t1"}}) → 读 response["__interrupt__"]（action_requests / review_configs）→ invoke(Command(resume={"decisions": [{"type": "approve"}]}), config=同一 thread)。decisions 长度必须等于挂起的工具调用数。

执行顺序（洋葱）

middleware=[A, B] 时，wrap_* 是 A 进 → B 进 → B 出 → A 出：列表越靠前越在外层。before_* 按列表顺序，after_* 反过来。

常见坑

  • bind_tools 只是把 schema 交给模型，不会执行工具；执行、回填 ToolMessage 得自己写。漏掉把 AIMessage 追加回历史再追加 ToolMessage，下一轮会报消息顺序错。
  • parse_docstring=True 只认 Google 风格（Args: 段）。NumPy 的 Parameters 段、Sphinx 的 :param:、没有 Args: 段的 docstring 都算无效，直接 ValueError: Found invalid Google-Style docstring.；error_on_invalid_docstring=False 才放行，放行后 description 退回整段原始 docstring，参数一个说明都没有（显式给了 description= 则仍用你给的那句）。
  • Args: 里写了签名中不存在的参数名，不管 error_on_invalid_docstring 给什么，都会抛 ValueError: Arg <名字> in docstring not found in function signature.——这个开关只管「格式是不是 Google 风格」，管不了名字对不对。
  • 函数没有 docstring 又没给 description=：默认报 ValueError: Function must have a docstring if description not provided.；parse_docstring=True 时报的是上面那条「invalid Google-Style docstring」。
  • ToolMessage.tool_call_id 是必填，且必须等于对应 tool_call["id"]；对不上模型会拒绝当前历史。
  • init_chat_model 写 "provider:model"，厂商包要装好（本项目用 langchain-deepseek）。没 key 时别硬调，先判 os.environ.get("DEEPSEEK_API_KEY")。
  • ChatPromptTemplate.from_messages 里想用变量就别塞 HumanMessage(content="{x}")，那是字面量；要用 ("human", "{x}") 或 HumanMessagePromptTemplate.from_template。
  • prompt.invoke(...) 返回的是 ChatPromptValue，不是 list；要消息列表用 .to_messages()，要字符串用 .to_string()。
  • PromptTemplate.format 出字符串，ChatPromptTemplate 想直接看消息用 format_messages；两者变量漏一个都会在格式化时报错。
  • LCEL 里 | 右边可以直接写 dict（会自动变 RunnableParallel）和普通函数（会自动变 RunnableLambda）；但写函数时入参只有一个，别按多参写。
  • RunnablePassthrough.assign 只在 dict 输入上补键，输入不是 dict 会失败；RunnableParallel 各路拿到的是同一份输入，不会互相看见对方输出。
  • RunnableBranch 最后一个参数是默认分支，不带条件；忘了它、又没条件命中时直接抛错。
  • TextSplitter 的 chunk_size=4000 / chunk_overlap=200 大得不像练习默认值，切短文本一定要显式写；RecursiveCharacterTextSplitter 把 keep_separator 默认改成了 True，和基类不同。
  • split_documents 保留 metadata，split_text 只给字符串，没有来源信息；要接向量库就用前者。
  • InMemoryVectorStore.similarity_search 的 k 默认是 4，不是 1；similarity_search_with_score 的 score 越小通常越相近，但它随实现不同，跨库别硬比。
  • as_retriever(search_kwargs={"k": 1}) 里 k 写在 search_kwargs 字典内；search_type 换个值就换策略。
  • FakeListChatModel / DeterministicFakeEmbedding 是测试替身，只用来离线跑通或写单测；正课一律用真模型 + 真 embedding。
  • langchain 主包只做重导出，报 ImportError 先确认路径：消息 / 提示 / 链基元在 langchain_core.*，切分器在 langchain_text_splitters，厂商模型在 langchain_<provider>。
  • 本机没装 langchain-community，TextLoader / Chroma 这些用不了；要用得先 pip install langchain-community（或对应集成包），而且签名以那个版本为准。
  • middleware 自定义字段必须挂 state_schema（继承 AgentState）；否则 return {"calls": ...} 会被静默丢弃，response 里没有这个键、也不报错。
  • ModelRequest.messages 不含 system；改系统指令用 request.override(system_prompt=...)，别往 messages 里硬塞。
  • wrap_* 是洋葱：middleware=[A, B] → A 进 → B 进 → B 出 → A 出；一次 invoke 里模型可能被调多次，这四行会重复。
  • HumanInTheLoopMiddleware 必须配 checkpointer + thread_id；Command(resume={"decisions": [...]}) 的列表长度要等于挂起的工具调用数，多一个少一个都 ValueError。
  • ModelCallLimitMiddleware 默认 exit_behavior='end'，ToolCallLimitMiddleware 默认 'continue'，两者默认不一样；要硬失败都显式写 'error'。
