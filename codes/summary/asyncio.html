A

速览

按主题分组的常用 API。签名与默认值对照本机 Python 3.14.6 核对，= 后面是默认值，没写默认值的表示必填。练习见 qa.ipynb，模块清单一览见 ../stdlib.md。

约定：

  • 异步函数用 async def 定义，调用它只得到协程对象，必须 await 或交给事件循环。
  • 阻塞调用（文件、requests、time.sleep）会卡死整个事件循环；要么用异步库，要么 asyncio.to_thread。
  • 入口统一用 asyncio.run(main())，别手动管 new_event_loop / run_until_complete。

运行与任务

名称 常用关键字参数 说明
run main、debug=None、loop_factory=None 建事件循环跑主协程，结束自动清理；同一线程只能调一次

shield arg 保护外层取消，不让取消传到内部任务

as_completed fs、timeout=None 按完成顺序产出可 await 的结果
TaskGroup — 结构化并发：async with TaskGroup() as tg: + tg.create_task(...)，子任务异常会取消整组（3.11+）
timeout delay 超时上下文管理器：async with asyncio.timeout(1):（3.11+）

使用用例

1. 跑一个协程

import asyncio
async def ping():
    return "pong"
print(await ping())

2. 中间停一下

import asyncio
async def tick():
    print("before")
    await asyncio.sleep(0.1)
    print("after")
await tick()

3. 一起等，顺序跟传入的一样

print(await asyncio.gather(fetch("slow"), fetch("fast")))

4. 先启动，再取结果

async def main():
    task = asyncio.create_task(load())
    print("started")
    print(await task)
await main()

5. 等太久就放弃

try:
    await asyncio.wait_for(slow(), 0.05)
except TimeoutError:
    print("TimeoutError")

6. 谁先做完谁先拿

tasks = [asyncio.create_task(work(name, seconds)) for name, seconds in jobs]
async for task in asyncio.as_completed(tasks):
    print(task.result())

常见坑

  • async def 的调用不会执行函数体，忘了 await、忘了 create_task，代码会静默不跑。
  • 在协程里直接调阻塞函数（time.sleep、同步 open）会卡住所有并发；换 await asyncio.sleep / to_thread。
  • asyncio.run 不能嵌套，也不能在已运行的循环里调；Jupyter 里用顶层 await。
  • gather 默认一旦有异常就往外抛，其余任务不一定被取消；要逐个收集结果用 return_exceptions=True 或 TaskGroup。
  • 忘记 await 一个协程会触发 RuntimeWarning: coroutine was never awaited，但不会报错。
  • create_task 返回的 Task 若不保存引用，可能被垃圾回收提前取消；把它放进变量或集合里。
  • get_event_loop 在没有运行循环时行为依赖版本，容易拿到废弃循环；新代码用 get_running_loop 或 asyncio.run。
  • TaskGroup body 里的异常会取消所有子任务并在退出时汇总成 ExceptionGroup，捕获时要 except*。
  • asyncio.iscoroutinefunction 从 3.14 起弃用，迁移到 inspect.iscoroutinefunction。
