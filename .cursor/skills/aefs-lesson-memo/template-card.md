# PNG 版式

英雄点按 SKILL 选；**一张** PNG；版式跟强调走，无固定分区。

## 画布

- 比例：`3:4` 默认；需纵向用 `9:16`
- 风格：手绘/软卡通/公众号卡；纸感或浅网格；墨线；粉彩
- 语言：中文为主（术语可英）
- 避免：干白底、紫光仪表盘

## 图层（可重排）

| 层 | 内容 | 注意 |
|----|------|------|
| 身份 | 眉头/标题/Motto/目标 | 轻，别抢主视觉 |
| 主视觉 | 1–2 必记点 | 最大：图解/代码/公式…；**图上勿写 HERO/英雄点** |
| 支撑 | 便签、数字钩、Build/Use | 仅澄清主视觉时用 |
| 边角 | 坑 | 小；不要自测 |

例：机制课管线居中、**双高生产代码贴主视觉旁**（如 device 选择）；公式课大号等式；工程课失败三格可当主视觉；模型课用**模块方块 + 箭头数据流**（残差/注意力等课文点名的连接要看得见）。缺席优于硬塞。架构若拆到 `archi-` 旁卡，本章卡不要再抄一遍框图。

**出图禁令（高频翻车）：** 勿把策划用语印成标签卡。图上不要 `HERO 1` / `HERO 2` / `英雄点` 色块；区块标题用内容本身（「消歧三招」「NIAH 热力图」）。`description` 里若写 layout，用「上区 / 下区 / 左侧主图」，勿写会被模型照抄的 `HERO XX`。

## 密度

手机可读；短标签；生产代码够 punchline 即可（1–3 行）。无 URL、无答案。

**图文平衡（两极都忌）：** 机制用图承载，关键部件要有可读短标签 + 必要时 1–2 句说明。  
勿长文墙 / 便签森林；也勿只剩图标、几乎无字、读者猜不出箭头含义。中段密度为准。
